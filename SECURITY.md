# Security policy

## Supported versions

Security fixes are provided for the latest released minor version. Before the first release, fixes are made on the default branch.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature for this repository. Do not open a public issue for a vulnerability that could expose users or CI systems. Include the affected version, reproduction steps, impact, and any suggested mitigation. The maintainer will acknowledge a complete report when available and coordinate disclosure after a fix is ready.

Safety-rule false negatives without a software security impact should use the false-positive/negative issue template, with synthetic reproduction data only.
